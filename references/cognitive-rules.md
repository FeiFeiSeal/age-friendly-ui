# Cognitive rules

以下是 **Age-friendly Recommendation**，若明確對應 WCAG，另以 [WCAG](wcag-2.2.md) 的條件判定，不以「減少認知負擔」籠統宣稱違規。

- **知道在哪裡**：頁面標題、目前區段與操作對象清楚；多步驟流程顯示進度。不是所有簡單頁面都需要 breadcrumb 或 stepper。
- **知道目前狀態**：區分未儲存、已儲存、已提交、處理中、完成；不要只用「成功」涵蓋不同結果。
- **知道下一步**：使用具體文字如「確認申請內容」，避免模糊「繼續」；多個選項需有優先順序和後果說明。
- **不靠回憶**：在做決定的地方顯示姓名、日期、金額或上一步摘要；返回修改保留輸入。若要求同流程再次輸入資訊，查 SC 3.3.7；只有跨頁記憶負擔並不自動構成該 SC 違規。
- **降低注意力切換**：按任務分組，讓提示靠近相關欄位；次要細節可漸進揭露，關鍵條件與危險後果不可藏起來。
- **保留熟悉度**：同一概念一致命名，同類操作位置穩定；改版先改善可辨識度，再考慮換導航或 interaction pattern。
- **能恢復**：返回、取消與復原語意分清；失敗保留有效輸入、篩選、頁次與操作對象；不要靠使用者自行記錄重建。

## UI specification review

引用 section／原句，區分「規格未定義」與「已實作但有問題」。逐一確認：

1. 主要任務入口、完成條件、離開與返回路徑。
2. 同名不同功能或同功能不同名；含糊「取消」究竟取消申請還是關閉視窗。
3. [狀態表](interaction-rules.md) 的 loading、processing、success、error、empty、warning，以及 disabled／selected。
4. 會影響該流程的 edge cases：重複提交、網路中斷／逾時、輸入錯誤、session 到期、權限不足、資料被他人更新、長內容與放大。
5. 破壞性操作的對象、範圍、可逆性、確認／復原策略；錯誤後哪些資料被保留、如何繼續。

對缺漏提出可交付給設計／開發的驗收文字，而非只說「需要更清楚」。未知技術策略可列待決策選項，不替產品默認不可實現的 undo。

依據：[older-users](older-users.md) 所列 WAI 與 COGA guidance。規格範例見 [ui-spec-review](../examples/ui-spec-review.md)。
